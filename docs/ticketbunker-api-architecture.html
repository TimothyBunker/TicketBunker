TicketBunker / Bunker architecture

One Bunker, one local database, optional team service

The desktop app owns the experience. A Bunker owns configuration, membership, Projects, and tickets. Git, agile providers, persistence engines, and the coworker remain replaceable tools behind one API.

Architecture contract

One door into the core

Every interface calls the same typed API. The core decides what an action means; adapters decide how it reaches a tool or external service.

Owns

Validation, orchestration, state transitions, and a stable vocabulary for the application.

Does not own

Provider-specific transport, user shell behavior, direct database access from views, or source-code changes by the coworker.

Four non-negotiables

  1. The app speaks only to TicketBunker.
  2. CLI automation, if retained, calls the same actions.
  3. Remote team state sits behind an authenticated service.
  4. Git and the coworker are tools, not the product boundary.
